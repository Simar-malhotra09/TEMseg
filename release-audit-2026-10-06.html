TEMseg release audit

6 October 2026 · Branch: audit/release-hardening-2026-10-06 · Review state: separate commits

This report covers code, a local macOS package build, API checks, and TEM measurement needs. It does not certify measurement accuracy on a new sample. The release decision must use reference images and an installed app on each target platform.

1. Release decision

Recommendation: hold the public release until the open gates in section 5 pass. The audit found errors that can change measured particle sizes, hide prior session data, or stop EMD import in a packaged app. The branch fixes several of these errors. The remaining gates concern measurement validation, upgrades, and target machines. The passing API suite is evidence of operation only. It is not evidence of scientific accuracy.

4. Scientific risks that the app must show to users

4.1 A TEM image is a projected view

Equivalent circle diameter comes from projected area. It is not a direct three-dimensional particle diameter. Touching particles, agglomerates, low contrast, and image thresholds change that area. Show the method name with every size result. Keep the mask next to the source image.

4.2 Sampling can dominate model error

A count of many particles from one field does not replace several independent fields. The app now reports particles that touch an edge. It does not yet make a documented rule for edge exclusion, field selection, or replicate weights. Add these rules before a user compares samples.

4.3 Calibration needs evidence

The app can record embedded, manual, or scale-bar calibration. It does not yet keep the scale-bar line coordinates or a calibration reference image. A lab must be able to check the line and the unit later. A wrong scale changes every physical size and every area by the square of that scale.

4.4 Fit labels need restraint

The app now uses AIC to rank three fitted distribution families. AIC ranks only the tested families. It does not prove that any family is correct. The small-sample threshold of ten particles is too low for a strong scientific fit claim. Report the raw sizes, field count, and plot with the fitted curve.

5. Open release gates and known limits

PriorityIssueRequired check or action
PassedConfirm packaged EMD import after the direct-reader fix.The second package passed the quick suite with EMD, TIFF, JPG, NPY, segmentation, and export.
P0Validate measurement quality.Use a calibrated reference material and blinded hand annotations. Report count error, diameter bias, repeatability, and missed touching particles by image type. State acceptance limits before the test.
P0Replace the mismatched ground-truth fixture.Pair each image with an annotation from that exact image. Record the image hash, mask hash, annotator, and review status. Then run quantitative accuracy checks.
P0 if users have prior sessionsOlder sessions can remain inside a prior app folder or the old development folder.Back up that folder before an update. Test a migration or an explicit export and import path. The new data path does not migrate old sessions automatically.
P1Windows and clean-machine startup remain unverified.Install on a clean Windows machine and a clean supported Mac. Check WebView2, GPU and CPU model paths, model downloads, permissions, long paths, and port conflicts.
P1Model files require about 1 GB of downloads before first use.Download only the models a user selects. Show total size, free space, retry state, and an offline install path.
P1Uploads and ZIP exports have no practical memory or disk budget.Set a size policy for TEM files. Stream ZIP output to disk or to the response. Test large TIFF and EMD files under low free space.
P1A local process can still call the loopback API. Browser requests with no Origin header are accepted.For a stricter desktop boundary, use a launch token for API calls and place it in the native bridge. Review compatibility with the static frontend.
P1Small particles below the fixed 50-pixel instance floor are dropped.Make the floor visible in physical units and test it against the image scale. Save the chosen value in the analysis manifest.
P2Missing requested export items are skipped. ZIP creation is in memory.Return a list of missing items or fail the request. Test a large source image export.
P2Build dependencies and signing need a release record.Pin the build toolchain, keep a software bill of materials, sign and notarize the Mac app, sign the Windows binary, and verify the installed artifacts.
P2The original source file can contain instrument or operator metadata.Warn users before they share an export. Offer a separate metadata review or scrub option for public data.

7. Literature and workflow basis

  • NIST: Measuring the size of nanoparticles using TEM. This source describes projected-size measurement and its limits.
  • NIST interlaboratory study of nanoparticle size by TEM. The study shows why repeatability and between-lab uncertainty matter.
  • NIST SP 1200-22: ImageJ-based TEM particle measurement protocol. The protocol informs calibration, threshold review, and measurement records.
  • ImageJ Analyze menu documentation. It lists edge exclusion, Feret measurements, ROI handling, and results export that users may expect.
  • SciPy goodness-of-fit documentation. It explains why fitted parameters need a different goodness-of-fit procedure.

8. Work not completed in this audit

The user asked me to pack up the work before the original one-hour work period ended. I stopped new feature changes and prepared reviewable commits. The following work remains:

  • Prior-session migration: I moved new runtime data to a stable user directory. I did not copy older sessions. A safe migration needs a backup and a test with real prior data. An app update may remove files that remain inside an old bundle.
  • Clean-machine release checks: I could use this Mac and its cached weights. I did not have a clean Windows machine, a clean Mac account, a signed installer, or an offline machine to test.
  • Reference accuracy: The supplied mask is not paired with the EMD image. I did not invent an accuracy result from it. A real annotated data set and acceptance limits are required.
  • Large-file and failure tests: I did not stress the API with multi-gigabyte images, full disks, interrupted downloads, or concurrent users. These can still fail on a new machine.
  • Planned analyst features: I did not add an edge exclusion switch, a Fiji ROI exchange, field-level statistics, or an uncertainty review queue. Section 6 gives small first versions.
  • Permission limit: Automatic approval review rejected a recursive deletion of a failed upload session. I used a staged upload file instead. It prevents a bad image from creating a session and passed a local test.
